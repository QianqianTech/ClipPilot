# 视频浏览助手深度审计与优化报告

审计日期：2026-09-28  
范围：`app/src/main`、Gradle 构建、Manifest 权限、自动启动状态机、无障碍服务、APK 静态验证和发布门禁。

## 当前架构

- `MainActivity` 负责多平台勾选、每平台 2–100 个视频配额、10–30 秒随机上滑策略、无障碍设置引导、一次性自动打开、持久化自动模式和会话停止。
- `AutoSwipeAccessibilityService` 按冻结的任务队列监听当前平台包名、每次转场随机等待 10–30 秒后发送上滑并在配额完成后拉起下一应用；0.5.0-dev 在用户明确开启内容定向后，仅读取当前目标视频页可访问文字并在本机筛选命中/排除/未知；0.4.0-dev 的评论文字读取仍需用户从通知栏暂停后明确请求，不读取账号或消息。
- `SessionCommandReceiver` 提供通知栏里的可见“停止会话”“暂停并读取”“填入草稿”“恢复浏览”入口；草稿填入只作用于已聚焦可编辑输入框，不包含发送动作。
- `SessionTaskQueue` 提供确定性的队列去重、序列化和配额边界处理；会话状态写入本地 `SharedPreferences`，启动时间用于 30 分钟总时长上限。
- 统一 Manifest 声明通知、常亮和 `INTERNET` 权限，并关闭明文流量；通过五个明确包名的 `<queries>` 检查目标应用，不扫描全部已安装应用。

### P0：0.4.0-dev 本地评论辅助

- 新增短时互动状态：页面文字最多保留 5 分钟，候选草稿最多保留 10 分钟；恢复、停止、超时、服务中断和服务重连都会清除。
- 通知栏“暂停并读取”会立即取消上滑和应用切换计时；只有确认当前目标包仍在前台时才读取可访问文字，不能读取时保持暂停并提示用户处理。
- 首页提供关键词与内容方向（共鸣、提问、补充观点、专业点评、轻松幽默），根据读取文本生成 3 条本地候选。控制文案、过短文字、危险词和重复候选会被拒绝。
- 候选由用户选择后才创建草稿。用户必须手动打开并聚焦目标应用的评论输入框，再从通知栏点“填入草稿”；服务不会点击发送/发布。
- `EngagementPolicy` 对微信、抖音、快手、B站等第三方包名一律拒绝自动点赞或收藏；当前没有第三方平台动作适配器、坐标点击或网络模型调用。

### P0：0.5.0-dev 本地内容定向

- 新增独立的“内容定向”开关、首次披露、想看/不想看词项、启动前校验和会话快照；运行中修改只影响下一会话，关闭时保持既有随机 10–30 秒上滑行为。
- 新增纯 Java 规则分类器：词项规范化/去重、强排除优先、正向命中、文字不足安全降级和会话内匿名指纹去重。页面文字只在服务内存中处理，偏好和诊断不记录页面原文。
- 服务状态机改为“分析 → 命中停留 / 无关跳过 / 未知跳过”。只有命中内容成功上滑后才增加平台视频配额；扫描数、未命中、排除、未知和连续未命中独立统计。
- 每个平台最多扫描目标数的 5 倍（上限 100），连续未命中达到 15 条也会跳过当前平台；通知栏和主页显示命中/目标及扫描/上限，避免无限刷取。
- 停止、首个目标打开失败、服务中断、销毁和通知栏停止均清除内容定向会话快照与统计；内容定向与评论草稿/互动状态独立。

### P0：0.6.2 模型网关、任务上限与随机节奏

- Gradle 统一为一个功能版本；同一个 debug/release 包同时提供本地候选和可选 HTTPS 模型网关配置，清单禁止明文流量。
- `ModelGatewayConfig` 只允许 HTTPS 根地址和三个固定服务端档位；更换地址会禁用网关并要求重新确认。供应商 API Key 不存在于 Android UI、偏好、日志或 APK。
- 模型网关请求必须经过“暂停页面 → 用户点击生成 → 数据范围披露 → 粘贴不落盘的设备令牌”路径。页面可访问文字被限制到 360 字，设备令牌只存在本次 Activity 内存。
- `ModelGatewayClient` 使用后台线程、5 秒连接超时、15 秒读取超时、返回候选二次安全/去重过滤。停止、恢复、关闭评论辅助、关闭网关和服务会话清理都会断开在途连接；网关失败、令牌失效和限流不触发自动重试、自动本地回退或自动发布。
- 新增 `gateway/CommentModelGateway`：服务端环境变量持有供应商 URL/API Key，Android 只使用网关；网关提供设备/后台鉴权、模型档位路由、12 秒供应商超时、内存限流、10 分钟幂等响应、提示注入隔离、候选过滤和带 CSP nonce 的管理页。档位配置不接受供应商密钥字段。
- 当前服务端最小实现尚未接入真实供应商、企业身份、持久审计、成本记账、数据删除作业或 TLS 反向代理；这些均不能由本地单元测试替代。
- 每个平台任务配额统一提升至 2–100；普通浏览和内容定向均从 10–30 秒闭区间随机选择下一次上滑等待时间。该随机性仅用于用户可见的浏览节奏，不作为平台规则或风控规避手段。

### P0：多平台分任务与自动切换

- 单目标 `target_package` 已升级为用户配置 `selected_packages` 与运行快照 `session_queue` 两层状态。当前会话冻结队列、随机节奏策略和配额，用户修改下次配置不会改变正在运行的批次。
- 支持微信视频号、抖音、快手、B站和快手极速版多选；未安装或没有启动入口的平台不可进入任务队列。
- 每个平台可分配 2–100 个视频任务。当前视频完成并上滑后计数；达到配额后自动启动下一应用，最后一个平台完成后自动停止。
- 自动切换后等待目标包进入前台；15 秒内未确认前台则记录诊断、跳过该平台并继续下一项，避免整批永久卡住。
- 通知栏与主页同时显示“当前平台视频进度 + 当前平台序号/总平台数”，结束摘要区分全部完成、部分跳过、用户停止和异常停止。
- Android 同一时刻只能有一个前台应用，因此实现语义是同批次顺序自动执行，而不是多应用并行手势。

## 本轮已修复

### P0：会话生命周期和误触发

原实现用窗口事件直接重排定时器，多个窗口事件可能不断推迟首次上滑；服务重连也会无条件清空状态；停止后重新开始可能沿用旧的开始时间和计数。

现在改为显式状态机：

- 会话开始时保存 `session_started_at`，30 分钟从用户启动会话起计算。
- 同一会话只允许一个待执行定时器和一个进行中的手势。
- 服务重连仅在启动后的短暂连接窗口内保留会话，普通重连会安全停止并要求重新启动。
- 服务中断、服务销毁、目标应用离开前台和用户停止都会清理运行状态。
- 新会话通过启动时间变化重新初始化计数，不会沿用旧会话数据。
- 自动浏览事件已修复：非目标包的 `TYPE_WINDOW_CONTENT_CHANGED` 只作为内容噪声忽略，不再取消待执行上滑；只有窗口状态/窗口集合变化才会判断离开前台，并在清理定时器前复核活动窗口。

### P1：可操作性和可撤销性

- 主按钮明确为“自动打开并执行”，省去先打开目标应用再启动会话的重复操作。
- 自动模式默认关闭；用户主动开启后，下次打开助手等待约 1 秒再执行。
- 运行通知增加“停止会话”动作，用户不需要切回助手页面才能撤销。
- 通知使用低重要性频道和 `setOnlyAlertOnce`，避免每次上滑产生提示音。
- 增加会话期间屏幕常亮开关；WakeLock 带 30 分钟超时，停止、超时、中断和服务销毁都会释放。

### P1：数据和构建质量

- 增加 Android 12 `dataExtractionRules` 和旧版本 `fullBackupContent`，禁止把目标包名、自动模式和会话状态迁移到其他设备。
- 清理 Android Lint 的 8 个问题：备份规则、无效 SDK 判断、未使用颜色资源和动态中文文本拼接。
- 开启 `warningsAsErrors`，后续新增 Lint 警告会阻止构建。
- release 变体可以完成资源、代码和 Lint 打包，但没有配置正式签名。

### P2：界面与交互优化

- 启动页整理为“使用边界、服务状态、执行设置、会话操作”四个卡片区块，减少长文本堆叠和重复按钮。
- 使用统一圆角、浅色背景、描边卡片和蓝色主按钮，建立“自动打开并执行”为主操作、“打开目标应用/停止会话”为次操作的视觉层级。
- 将两个复选框改为开关控件；上滑时间使用“随机 10–30 秒”说明胶囊展示；服务与会话状态增加颜色状态点。
- 0.2.x 的单目标选择会保存在本机；0.3.0 已将其兼容迁移为多平台勾选配置，并继续保留无障碍、自动执行、停止和常亮能力。

### P0：debug 无障碍服务识别修复

- debug APK 的安装包名为 `com.example.videobrowseassistant.debug`，无障碍服务类仍是 `com.example.videobrowseassistant.AutoSwipeAccessibilityService`。
- 原逻辑通过相对类名拼接检查启用状态，会在 debug APK 中构造出错误的服务组件名，导致用户已在系统设置开启服务后，应用仍显示“未开启”，并拦截会话启动。
- 现改为根据 `AutoSwipeAccessibilityService.class` 构造完整组件名，debug 与 release 均按系统实际记录判断。
- 主操作位于平台选择下方：服务未开启时显示“去开启无障碍服务”，开启后显示“启动 N 个平台任务”，避免“选择后无响应”的误解。

### P1：设备差异运行诊断

- 增加“运行诊断”卡片，展示最近 10 条本机记录，并可复制或清除。
- 日志记录设备厂商、型号、Android 版本和应用版本，以及服务连接、服务中断、应用启动、通知权限、手势提交、手势取消、系统拒绝手势和会话停止原因。
- 打开目标应用失败会显示系统异常类型和可用异常信息，并立即清除刚创建的会话状态，避免界面显示运行中但实际未启动。
- 日志最多保留 18 条，仅存储在本机 `SharedPreferences`，不记录账号、内容、消息或网络数据。

### P0：真机无障碍设置路径修复

- 真机截图确认“去设置”打开的是系统“无障碍”总页面，当前屏幕显示的是音频、字幕和视觉选项，并不表示本服务配置失败。
- 服务卡片现在明确提示用户向下找到“已下载的应用”或“已安装的服务”，选择“视频浏览助手无障碍服务”后手动开启；启动会话时的提示和本地诊断也会记录同一条路径。
- 新增“找不到服务？打开应用详情”入口。若厂商系统将侧载 APK 标为受限设置，用户可在系统应用详情页的右上角更多菜单中查找“允许受限设置”，再返回无障碍页重试。
- 启动页会读取当前 APK 的 `ServiceInfo`，区分服务未被系统识别、服务被禁用、缺少 `BIND_ACCESSIBILITY_SERVICE` 声明、缺少无障碍元数据和“已正确声明但尚未由用户开启”五类情况。应用不会尝试绕过系统的无障碍授权。

## 仍然开放的验收项

- 尚未在 Android 10+ 真机验证系统无障碍授权、目标应用包名、通知栏停止动作、厂商后台限制和 30 分钟超时。
- 尚未在该截图对应的真机确认“已下载的应用/已安装的服务”的实际位置，以及 Android 13+ 侧载 APK 的“允许受限设置”菜单路径；这些属于厂商系统和安装来源的验收项。
- 屏幕常亮功能尚未在真实设备上验证系统息屏策略、锁屏策略和不同厂商的电量管理行为。
- 抖音、快手、微信和 B站的浏览调度仍只做包级前台判断；微信必须由用户先进入视频号，B站必须先进入竖屏视频页。0.5.0-dev 的内容定向和 0.4.0-dev 的评论辅助会读取可访问文字，但各平台节点可用性、文字质量、内容命中准确率、扫描上限和草稿填入兼容性均未真机验证。
- 模型网关代码、后台档位配置和本地模拟测试已完成，但没有真实模型供应商凭证、设备短期令牌签发、TLS 反向代理、数据留存/删除审批、成本计量或端到端真机请求证据。在线能力必须保持关闭，直到这些条件完成。
- 多应用自动切换依赖 Android 和厂商允许无障碍服务拉起下一应用；15 秒超时/跳过已完成代码验证，但真实切换和页面恢复仍需真机验收。
- release 未配置正式 keystore、隐私政策、无障碍用途声明、商店审核材料和兼容性矩阵。
- Android 不能保证后台直接启动第三方 Activity；当前自动模式严格绑定到用户打开助手这一前台触发，不实现开机隐式拉起。

## 建议的下一步

1. 在一台测试真机完成清单中的 `VERIFY` 项，优先验证停止动作和服务重连。
2. 根据目标设备补充横竖屏、分辨率、系统导航栏和厂商省电策略记录。
3. 若要正式分发，先完成平台政策和无障碍用途审核，再配置独立 release keystore 和可回滚发布流程。

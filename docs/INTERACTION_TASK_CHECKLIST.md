# 视频浏览助手：智能互动（点赞、收藏、关联评论）任务清单

版本目标：`0.6.2`（统一模型网关配置已实现，真实供应商联调待验收）  
适用工程：`VideoBrowseAssistant`  
状态：`DONE` 已有基础，`TODO` 待开发，`VERIFY` 待测试或真机验收，`HOLD` 需平台规则、授权或发布条件确认。

## 1. 产品结论与范围

- “自动点赞”和“自动收藏”默认关闭，仅允许用户在每次会话中明确开启；未经目标平台规则确认时，只能在自有应用、测试应用或获得授权的环境中启用。
- “智能关联评论”在用户授权后提取当前视频的最少必要标题、字幕、语音或画面语义，结合自定义关键词、内容方向和语气生成 3 条候选；公开平台最终“发送”必须由用户亲自确认。
- “随机评论”定义为：在满足相关性、安全性和去重阈值的候选中随机选择，或按用户设定比例抽取合格视频进入评论流程；评论随机选择不使用随机坐标或伪装真人来规避平台风控。浏览任务的 10–30 秒随机等待是独立的用户可见节奏设置。
- 第一阶段动作范围为点赞、收藏、评论辅助。关注、分享、私信、购买和下载不默认纳入，只预留受控扩展接口。
- 点赞、收藏和评论都必须受到前台应用、页面识别、会话时限、独立次数上限、显式停止和脱敏诊断约束；页面或动作状态不确定时不执行。
- 统一版本声明 `INTERNET` 并拒绝明文流量；模型功能只能通过服务端模型网关调用，APK 内不得保存模型密钥，设备令牌也只保留在本次应用内存。

## 12. 推荐实施顺序

1. 先完成 `INT-P0-01`～`INT-P0-14`，锁定规则、限额和状态机。
2. 开发 `COM-P0-01`～`COM-P0-11`，先交付“暂停并评论 + 人工发送”的基础链路。
3. 实现 `AI-P0-01`～`AI-P0-21`，先以页面文本生成 3 条高关联候选，再逐步接入用户授权的语音/画面分析。
4. 在自有测试 Activity 完成 `ENG-P1-*`、`LIKE-P1-*`、`FAV-P1-*`，证明页面识别、幂等和失败关闭。
5. 完成 `AI-P0-22`～`AI-P0-25`、`ACC-P1-*` 和 `TEST-P0-*`，再逐个平台进入真机适配。
6. 只有对应平台 `INT-P0-01`、G6 和 G8 通过，才解除 `LIKE-P1-09` 的 `HOLD`。
7. 最后执行发布材料、正式签名与回滚门禁；未通过时保持 debug/测试用途。

## 13. 最小可交付版本（MVP）

MVP 包含：通知栏“暂停并评论”、文本优先的视频理解、关键词/内容方向、3 条高关联候选、安全与去重过滤、用户选中后辅助填写但不发送、显式恢复、全链路停止和脱敏诊断。自动点赞和自动收藏先在自有测试页验证，不纳入首个公开测试包。

## 14. 关键外部门槛参考

- [Google Play：AccessibilityService API 使用政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=zh-Hans)：非无障碍工具需要显著披露与同意；自动化必须保持目的窄、行为清晰，并在上架前完成声明与审核。
- [Android：视频与播放音频采集](https://developer.android.com/media/platform/av-capture)：屏幕/播放音频分析需要系统授权，来源应用可禁止被捕获，用户也可随时撤销。
- [Android：MediaProjection](https://developer.android.com/media/grow/media-projection)：面向较新 Android 版本时，每次采集会话都必须重新取得用户同意并正确处理停止回调。
